# Feature inventory

Confidence describes evidence of implementation/call paths in this checkout, not runtime validation. Validation suggestions are future checks; none were run during this audit.

| Feature | Likely owner / observed entry points and callers | Confidence | How to validate |
|---|---|---|---|
| Startup / lifecycle | `main.py` -> `app.marklv.main.main()` -> `JarvisUI` + background `JarvisLive.run()`; DIMO CLI functions also live in root `main.py` but are not selected by its dispatcher. | confirmed active (Mark-LV); possibly active (DIMO graph CLI) | Launch from a disposable environment; confirm selected UI, shutdown and reconnect. Separately call the DIMO CLI entry only after establishing a supported invocation. |
| GUI / HUD / avatar | `app/marklv/ui.py` defines Qt UI, HUD, chat text command callbacks, settings, plugin and memory views; `app/marklv/core/avatar.py`, `avatar_mesh.py`, `viseme.py` render/animate avatar. `JarvisLive` wires UI callbacks in `app/marklv/main.py`. | confirmed active | Manual startup, text command, HUD, settings, avatar fallback and shutdown checks on supported desktop OS. |
| Voice | Mark-LV `JarvisLive` connects Gemini Live audio through `app/marklv/core/gemini.py`, plus `core/stt.py`, `tts.py`, `wake_word.py`, `hotkey.py`, `echo.py`, `audio_devices.py`. DIMO's distinct offline voice pipeline is `app/nodes/voice.py`, called by root `main_voice()` only. | confirmed active (Mark-LV); possibly active (DIMO) | Hardware checks: mic/speaker, interruption, PTT/wake word, transcription, playback, device changes and reconnect. Validate network state separately. |
| Model routing | Mark-LV `core/llm_client.py` reads selected AI engine from memory config and supports Ollama/OpenAI-compatible calls; `core/gemini.py` selects/fails over Gemini Live models. `JarvisLive` reads configured engine. No evidence supports a blanket offline claim. |
| Mark-LV inline actions | Inline `TOOL_DECLARATIONS` and dispatch in `app/marklv/main.py`; action modules in `app/marklv/actions/`. | DIMO tools | `app/tools/registry.py` populates `TOOL_CATALOG` from native tools and browser catalogs; `app/nodes/loop.py` validates and executes; node flow built in `app/graph/graph.py`. | Plugins / dynamic loading | Mark-LV `core/plugin_loader.py` scans non-underscore `plugins/*.py`, imports by path, validates `PLUGIN`; `app/marklv/main.py` discovers and advertises. `core/action_loader.py` scans `actions/*.py` for `TOOL`. Never treat similar action/plugin names as duplicates without call-site evidence. |
| Memory | Mark-LV `memory/memory_manager.py` stores JSON, formats prompt memory, searches, and maintains session summaries; used by `JarvisLive` and UI. DIMO `app/memory/memory_manager.py` uses gateway-backed extraction and `app/memory/long_term.json`; root DIMO CLI invokes background extraction after graph turns. | confirmed active (Mark-LV); possibly active (DIMO) | Disposable config/data directory; save/search/forget, prompt inclusion, summary lifecycle, local-only and cloud extraction paths. |

| Confirmation gates | Mark-LV `core/confirm.py` issues interface-held confirmation tokens; `JarvisLive` binds UI confirmation methods. Prompt explains interface approval. | Undo / reversal | Mark-LV `core/undo.py` keeps in-memory undo stack; Mark-LV action modules opt in. | Configuration | Mark-LV `memory/config_manager.py` persists API key, selected engine, UI/audio/plugin settings in `app/marklv/config/api_keys.json`; `core/gemini.py` reads key there. | Browser / external integrations | Mark-LV actions use requests/browser automation and optional Gemini; DIMO `BrowserManager` is a Playwright singleton and registry exposes tabs/search/WhatsApp/Gemini tools. DIMO services add weather, flights, messaging, vision, files and system actions. | confirmed active (Mark-LV subsets); possibly active (DIMO path) | Mock network where possible; service-by-service logged-in browser and API checks only in a test profile. |

## Overlap caution

Both families have separate graph/model/tool/memory/voice/browser systems and similarly named features. DIMO wrappers import Mark-LV `core.confirm` and `core.undo`; that is evidence of a bridge and shared runtime assumptions, not proof either subsystem can be removed. All consolidation/removal proposals remain **not approved for deletion** until runtime and test validation exists.
